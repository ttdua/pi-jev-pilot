# Evidence: 0.1 release report, 2026-11-08

This is the 0.1 release report. It runs the shipped Jev questions over one operator's real sessions: 100 main prompts and 200 worker briefs, each sent twice, so that the difference between the two runs is the noise floor. It shows where Jev routes samples in each mode, with and without a reviewer slot, and how much of that routing is noise. The figures are counts from one operator's data. Prompts, briefs, answers and scripts are not in this repository. The method is in [Testing](../testing.md#release-report).

**Read with care:**
- These numbers show routing, not quality. Nothing here says a routed model does the work well.
- There is one operator, over two weeks. This is a small sample.
- The `tiers` routing is an approximation: it ignores the slot's probability in the same answers instead of asking Jev again without the slot.
- The start effort comes from sessions run with the earlier port, so "vs start" mixes manual levels with the port's own decisions.

## Method notes

- **Sample order.** The 200 worker launches are routed in sample order, not in launch time. The first 100 launches use the seed cut points. The later launches use a rolling window of the latest 200 entries, built with the package's own `windowEntries` and `cutPointsFor`. The #39 method also used extraction order.
- **Capabilities snapshot.** The snapshot was taken with `bun tests/host/manual/capabilities-snapshot.ts <scratch>/capabilities.json`, then extended with the agent files of the earlier setup: the `naicoi92/pi-subagents` agents and the `pi-superspec` agents named `superspec.*`. The package's own agent reader parsed them, because most briefs in the corpus were launched with those agents. No brief was excluded.
- **`tiers` approximation.** The tiers-only routing drops the `reviewer` slot from the offered targets and ignores its probability, using the same answers. It does not ask Jev again without the slot. The `slots` routing applies the configured slot and is the closer picture of a real launch.
- **Start effort origin.** The start effort comes from sessions run with the earlier port. "vs start" therefore mixes manual levels and the port's decisions. The fixed-level comparison is given next to it for that reason.
- **Commands.** The report run is:
  1. `bun tests/host/manual/capabilities-snapshot.ts <scratch>/capabilities.json`, extended with the earlier agent files as described above.
  2. `bun scripts/replay/cli.ts --pass report --capabilities <file>`: the dry run, which prints the request count and the estimated cost.
  3. `bun scripts/replay/cli.ts --pass report --capabilities <file> --send`: after the operator approved the data and the cost.

## Reading

- **Jev chooses `low` for most main prompts.** 74% of the report samples and 75% of the rerun samples decided `low`. Against the start effort, 38 of 43 were the same; against the fixed level `low`, 5 of 43 were raised and none lowered.
- **Main-effort noise is small.** 4 of 100 decisions changed between the report and the rerun, so differences of that size are not results.
- **Tier shares sit within 10 points of the mode targets.** This holds for every mode in both runs, in the tiers-only mix. Percentages here count all 200 launches, including the first 100 routed on the seed.
- **The reviewer slot takes the reviews.** In every mode, 99 or 100 of the 100 review briefs go to the slot, and 5 of the 100 non-review briefs do too.
- **Routing noise is larger without the slot.** Between the report and the rerun, 4.5–8% of tiers-only launches changed tier, against 1.5–2% with the slot.
