## Issues

### CRITICAL

- **C1 — `disallowed_tools` bypass for launches without a schema.** `src/lifecycle/create-subagent-session.ts:328`. Violates the "No schema" scenario (child has no `submit_result` tool, tool count unchanged) and the global constraint that launches without a schema keep today's tools. **Fix:** apply the exemption only when `params.resultSchema` is set (when the launch installs the protocol tool); add a test: no schema, agent declares and disallows a parent tool named `submit_result` → the child does not have it and its tool count equals the base behaviour.
- **C2 — invalid second submission does not report "already submitted".** `src/session/submit-result-tool.ts:51–61`. Violates "First valid submission is final" (SHALL return an error saying a result was already submitted). **Fix:** have the tool check whether the run already holds a result before validating (for example a `hasResult()` query on the sink, or check-then-validate inside the sink), and return `ALREADY_SUBMITTED_TEXT` for any later call; add a test through the real tool and `SubagentRun`: valid then invalid → already-submitted error, value unchanged.

### WARNING

- **W1 — partial scenario coverage (9 scenarios).** Add the missing assertions: background launch with all three protocol tools; tool-level errors for an extra property and a fractional integer property; a real ceiling-turn run (`maxTurns` reached) for submit alone and mixed batch; turn-limit run asserting both `aborted` and the error; resume after a pending question then submit (asserting no error); free-text `result` kept when never called; two invalid calls then settle `"invalid"`.
- **W2 — design/contract drift.** Update design.md "Ending the run after the current turn", the `TurnLoopOptions` Contracts entry and apply.md "Contract deviations" to record the unawaited `session.abort()`, that queued steer/follow-up messages stay queued, and why the run still settles `completed`.
