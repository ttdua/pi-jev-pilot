### WARNING

- **W1: Codex is not covered by the fork cache-routing requirement.**
  - *Problem.* "Fork child session" requires the parent's session id as the provider cache-routing key. On `openai-codex-responses`, pi-ai overwrites `session-id` and `x-client-request-id` after the hook, so a Codex fork keeps its own id there. This is documented in ADR 0014 `:44`, `E:62–64` and `design.md` Spike results, but the requirement text has no exception.
  - *Recommendation.* Before archive, either add a scoped exception to the requirement ("except where the provider API overwrites the routing headers after extension hooks; currently `openai-codex-responses`"), or add a follow-up issue to fix it upstream in pi-ai or with a Codex-specific transport hook.
- **W2: The plan's Scenario → test table has two errors.**
  - "Policy over caller" points to `model-resolver.test.ts`, but the real test is `packages/pi-subagents/test/seams/launch-policy.test.ts:980`.
  - "Floor measured", added at Task 7, has no row.
  - *Recommendation.* Fix both rows in `plan.md`.
- **W3: The persisted-record Contracts row disagrees with the code.**
  - The row describes `context`/`contextFallback` narrowly, while `packages/pi-subagents/src/persisted-record.ts:35` types `context` as `ContextMode`.
  - *Recommendation.* Update the Contracts row to say `context?: ContextMode` (absent means fresh). The code is correct.
- **W4: Some contract rows are checked by compile only.** `AgentIdentity`/`AgentPromptConfig`, the assembly-internals deviation, the spawn plumbing options, and the fork stubs plumbing are verified by typecheck and behaviour tests, not by reading each declaration.
  - *Recommendation.* No action needed for merge. Optionally, in a follow-up, give stubs a unit test on the declaration shape (name, description, parameters equal to the parent's).
